# 化合物解析系统 · 功能说明

本文描述当前仓库（`frontend/` + `backend/`）已实现的产品能力，面向使用与联调，不替代算法细节文档（算法见 [项目总结.md](./项目总结.md)）。

---

## 1. 产品定位

从 ChemDraw 导出的 **CDXML** 文件中：

1. **结构解析**：识别分子结构，转为 SMILES，并按版面几何规则匹配化合物编号（HW）、tPSA、CLogP 与其它说明文字；
2. **文本结构化（可选）**：对匹配到的「待解析文字」调用 OpenAI 兼容大模型，拆成多张药化/ADME 相关数据表，并按化合物 ID 横向合并展示与导出。

主入口为 **Web 界面**；同时提供 **FastAPI** 与 **命令行**（`python -m cdxml_parser`）。

---

## 2. 系统组成

| 部分 | 路径 | 职责 |
|------|------|------|
| 前端 | `frontend/` | Vue 3 + Element Plus：上传、解析流程、结果表、设置、导入导出 |
| 后端 API | `backend/app/` | FastAPI：解析、AI 配置、文本结构化、合并、CSV 导出 |
| 解析核心 | `backend/cdxml_parser/` | CDXML 解析匹配、AI 批量、schema、连表合并 |
| 配置 | `backend/config/` | AI 配置示例与本地配置（`ai_config.json` 不入库） |
| 示例 | `samples/` | 示例 CDXML / CSV |
| 测试 | `backend/tests/` | text_ai 相关单元测试 |

本地一键启动：`./scripts/dev.sh`（API `:8000`，前端 `:5173`，`/api` 代理到后端）。

## 3. 结构解析

### 3.1 功能概述

上传 CDXML 后，后端读取页面中的 fragment 与文字节点，完成：

- 结构 → SMILES（RDKit）
- HW 编号 ↔ 结构的空间匹配
- tPSA / CLogP ↔ 结构匹配
- 其它说明文字 ↔ 结构匹配（写入结果字段 `text`）

输出主表字段：

| 字段 | 说明 |
|------|------|
| Compound_ID | 化合物编号（如 HW…） |
| structure | SMILES |
| tPSA | 匹配到的 tPSA 值 |
| CLogP | 匹配到的 CLogP 值 |
| text | 匹配到的其它说明文字（供后续 AI 结构化） |

另输出：

- **未匹配结构**：未能配对到 HW 的结构（含序号、坐标、边界框），便于人工审查；
- **未匹配 HW**：未能配对到结构的编号（API/日志侧有相应数据）；
- **运行日志**：解析过程说明。

### 3.2 可调匹配参数

| 参数 | 默认 | 作用 |
|------|------|------|
| 结构 X 左扩展 | 0 | 结构包围框向左扩展后再与文字做 X 重叠判断 |
| 结构 X 右扩展 | 0 | 结构包围框向右扩展 |
| 结构 Y 向下匹配数值 | 130 | HW / 属性 / 其它文字与结构之间的距离上限（CDXML 坐标单位） |

前端在「结构匹配设置」面板中调整；提交解析时随表单传给 `/api/parse`。命令行对应 `--match-x-left` / `--match-x-right` / `--match-y-down`。

### 3.3 前端操作

| 操作 | 说明 |
|------|------|
| 上传 CDXML 文件 | 选择本地 `.cdxml` |
| 开始解析 | 仅做结构解析，填充「化合物结构解析结果」「未匹配结构」等 |
| 自动执行 | 先结构解析，再对可解析条目自动跑文本结构化（并排除无法解析内容） |

### 3.4 相关 API / CLI

- `POST /api/parse`：上传文件 + 匹配参数 → JSON（compounds、unmatched_*、logs 等）
- CLI：`cd backend && PYTHONPATH=. python -m cdxml_parser <file.cdxml> -o out.csv`

## 4. AI 文本结构化

### 4.1 功能概述

在结构解析得到带 `text` 的化合物列表后，对每条（或勾选范围）调用大模型，将自由文本拆成 **6 张表**：

| 表名（内部） | 导出文件名 | 内容方向 |
|--------------|------------|----------|
| ic50 | IC50.csv | 细胞系、IC50、对照、构型等 |
| auc | AUC0_t.csv | 种属、给药途径（PO/IV）、AUC、F%、剂量等 |
| fu | Fu.csv | 种属、Fu(%) |
| solubility | Solubility.csv | 溶出介质、溶解度、pH |
| mms | MMS_T12.csv | 种属、MMS T1/2、检测方法 |
| cyp_inhibition | CYP_inhibition.csv | CYP 亚型、浓度、抑制率 |

字段定义与校验见 `backend/cdxml_parser/text_ai/schema.py`。

### 4.2 AI 配置项

前端「AI 解析设置」面板（后端持久化到 `backend/config/ai_config.json`，也可用环境变量 `CDXML_AI_API_KEY` / `CDXML_AI_CONFIG`）：

| 配置 | 说明 |
|------|------|
| Base URL | OpenAI 兼容接口地址 |
| API Key | 密钥（接口回传时脱敏，不在 GET 中回明文） |
| Model | 模型名 |
| 并发数 | 批量请求并发 |
| System / User Prompt | 系统提示词与用户模板（可自定义） |

支持 **测试连接**（`POST /api/ai-config/test`）。批量解析支持缓存目录（默认项目下 `.cache/text_ai`，可用 `CDXML_AI_CACHE_DIR` 覆盖）。

### 4.3 前端操作

| 操作 | 说明 |
|------|------|
| 文本解析 | 对当前结构解析结果中有 `text` 的条目做 AI 结构化 |
| 进度展示 | 设置面板 / 状态区显示批量进度 |
| 解析失败文本 Tab | 展示 AI 失败条目（Compound_ID、原因、原文） |

要求：须先完成结构解析；须已配置可用的 API Key。

### 4.4 连表合并

6 表按 **Compound_ID** 横向合并为一张「结构化数据表」：

- 同一 ID 的第 N 条记录横向对齐；
- 行数取该 ID 在各表中的最大条数；
- **不丢弃** 同 ID 的多条记录；
- 前端用两级表头展示（`Compound_ID` + 各表字段组）。

相关：`POST /api/text-ai`（可 SSE 流式进度）、`POST /api/merge-tables`。

## 5. 结果浏览与导出 / 导入

### 5.1 主界面 Tab

| Tab | 内容 |
|-----|------|
| 化合物结构解析结果 | Compound_ID、结构图、SMILES、tPSA、CLogP、待解析文字 |
| 未匹配结构 | 未配对 HW 的结构及几何信息 |
| 结构化数据表 | AI 拆表后的横向合并结果 |
| 解析失败文本 | AI 结构化失败明细 |

结构列使用前端分子渲染（SMILES → 结构式预览）。四个 Tab 的数据列表均使用 **vxe-table** 呈现；其中「化合物结构解析结果」「结构化数据表」支持 **双击单元格** 行内编辑（结构预览列除外，可双击改 SMILES 后刷新结构图）。编辑结果会反映到导出 CSV。

开发调试入口（AI 解析设置、运行日志、导出审查清单）默认隐藏，按 **Ctrl+Alt+-** 切换显示。

### 5.2 底栏能力

| 能力 | 说明 |
|------|------|
| 运行日志 | 查看本次解析 / AI 过程日志（开发调试模式） |
| 导出化合物结构解析结果 | 主结果 CSV（Compound_ID / structure / tPSA / CLogP / text） |
| 导出审查清单 | 未匹配结构等审查用 CSV（开发调试模式） |
| 导出结构化数据表 | 6 表 CSV（及合并相关导出，经 `/api/export/structured-csv`） |
| 导入化合物结构 | 导入结构类数据（前端入口，各 Tab 可见） |
| 导入化合物数据 | 导入已有结构化/表格数据并重新合并展示（各 Tab 可见） |

后端导出接口：

- `POST /api/export/main-csv`
- `POST /api/export/structured-csv`

## 6. API 一览

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/health` | 健康检查 |
| GET | `/api/ai-config` | 读取 AI 配置（Key 脱敏） |
| POST | `/api/ai-config` | 保存 AI 配置 |
| POST | `/api/ai-config/test` | 测试 API 连通性 |
| POST | `/api/parse` | CDXML 结构解析 |
| POST | `/api/text-ai` | 文本 AI 结构化（支持进度流） |
| POST | `/api/merge-tables` | 按 Compound_ID 合并 6 表 |
| POST | `/api/export/main-csv` | 导出主结果 CSV 内容 |
| POST | `/api/export/structured-csv` | 导出结构化多表 CSV |

交互式文档：后端启动后访问 `http://127.0.0.1:8000/docs`。

## 7. 典型使用流程

```text
上传 CDXML
    → 调整结构匹配参数（可选）
    →「开始解析」或「自动执行」
    → 查看结构解析结果 / 未匹配结构，必要时改参数重跑
    → 配置 AI（Base URL / Key / Model）
    →「文本解析」（若未走自动执行）
    → 查看结构化数据表 / 失败文本
    → 导出主表、审查清单或结构化 CSV
```

命令行仅结构解析示例：

```bash
cd backend
PYTHONPATH=. python -m cdxml_parser ../samples/cdxml/EO018\ compounds\ list.cdxml -o out.csv
```

## 8. 非功能说明

- **架构**：前后端分离；浏览器只调 `/api`，不直接依赖本机 Python 包路径。
- **安全**：AI Key 落盘在本地配置文件，GET 接口不回传明文；生产环境请自行限制 CORS 与访问控制（当前开发态 CORS 较宽松）。
- **依赖**：解析依赖 RDKit；AI 依赖可访问的 OpenAI 兼容服务。
- **测试**：`cd backend && PYTHONPATH=. pytest tests/` 覆盖 schema / JSON 解析 / 导出 / 连表合并等。
