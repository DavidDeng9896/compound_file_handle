# 结构优先：文字归属与匹配内去重

## 背景

现流程以 **HW 驱动**：每个 HW 去抢最近结构。CDXML 中一旦出现重合/重复 HW，就会多占下方结构，并把其他文字一并带偏。

目标：一次性消除「重复标签 / 跨结构抢占」这类问题，而不是逐个补丁。

## 决策（已确认）

| 项 | 选择 |
|----|------|
| 匹配主轴 | **结构优先**：由结构认领文字 |
| Y 规则 | **分区**：HW / tPSA / CLogP 用「结构附近」；其他文字用「底边→下一结构顶边」向下带 |
| 去重位置 | **在结构匹配内**：每种文字对每个结构最多一条；每条文字全局最多归属一个结构 |
| 输出 | 仍只输出「成功认领到 HW」的结构为化合物 |

## 设计

### 1. 结构归属区

对每个结构 `S`，先算同列下一结构 `next = find_next_structure_below(S)`。

**HW / tPSA / CLogP（附近区）**

- X：与 `S` 扩展后重叠
- Y：`hw_vertically_plausible`（文字底边不低于 `S.y1`）
- 距离：到结构中心 `< match_y_down`
- 不跨入下一结构「更合理」的领地：若文字中心 Y `>= next.y1`，则不算本结构候选（有 next 时）

**其他文字（向下带，沿用既有规则）**

- X 重叠
- 文字顶边 `y1 ∈ [S.y2, min(S.y2+match_y_down, next.y1)]`

### 2. 匹配内独占去重（核心）

对每一类文字（HW / tPSA / CLogP / other）统一两阶段：

1. 生成候选边 `(structure_i, text_k, dist)`
2. 按 `dist` 升序贪心：  
   - 每个结构对该类最多认领 **1** 条（other 允许多条，但仍是文字侧独占）  
   - 每条文字全局只用一次  

这样即使页面上有两个重合的 `HW356041`：

- 上方结构先按距离拿走其中一条
- 下方结构因垂直区/下一结构边界根本进不了该 HW 的候选，或文字已被占用
- **不会**再出现「第二个 HW 抢走下一结构」

重合文本的 content+bbox 预去重可保留作防御，但不再是唯一防线。

### 3. 主流程

```
收集 structures / hw / tpsa / clogp / other
→（可选）content+bbox 预去重
→ 结构优先：独占匹配 HW → 得到 compounds
→ 对 compounds 独占匹配 tPSA、CLogP
→ 对 compounds 独占匹配 other（多条按距离拼接）
→ 导出
```

### 4. 不变

- X 扩展参数、`match_y_down` 默认、HW 末尾括号清洗、AI 六表逻辑
- SMILES / CSV 字段

## 测试

- 结构优先：两结构 + 重合双 HW → 只有上方结构得 HW；下方结构匹配自己的 HW
- 独占：同一 HW 不能分给两个结构
- 其他文字 Y 带仍被 next 封顶
- EO035 回归：`HW356041` 仅 1 条且其他文字正确；`HW356047` 拿回原其他文字
